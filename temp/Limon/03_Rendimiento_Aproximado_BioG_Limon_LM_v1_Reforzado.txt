================================================================================
0. DECISIONES EJECUTIVAS Y CORRECCIONES
================================================================================

0.1. Enfoque correcto
Este documento modela rendimiento de LIMÓN / LIMONERO como cultivo comercial BIO-G, no un cítrico genérico.

Incluye perfiles LM:
- lm_skip — Limón general / No sé.
- lm_01_persa_tahiti — Limón Persa / Tahití / sin semilla.
- lm_02_mexicano_colima — Limón Mexicano / Colima / criollo / con semilla.
- lm_03_amarillo_eureka_lisbon — Limón amarillo / italiano / Eureka / Lisbon.
- lm_04_tropical_continuo — Tropical / producción continua.
- lm_05_desfase_inducido — Desfase / inducido / “de invierno” / ventana cara.

No modela naranjo, mandarina, toronja, lima dulce, naranja agria ni ornamental. Naranjo ya tiene su propio `crop_orange_tree`; sus kg/arbol y t/ha NO deben heredarse como si fueran limón.

0.2. Corrección de cropId
Los PDFs base usaban `LM-AR (crop_lime_tree)` para limón verde mexicano. Para BIO-G v1 se recomienda usar `crop_lemon_tree` como cropId canónico porque el usuario mexicano ve “Limón / Limonero” y los perfiles cubren tanto limes botánicos como true lemon amarillo.

Regla de compatibilidad:
- crop_lemon_tree = canónico recomendado.
- lemon_tree = cropKey esperado.
- crop_lime_tree, lime_tree, lime = aliases compatibles.
- Los profileIds LM no cambian aunque internamente se acepte lime/lemon.

0.3. Unidad principal
La salida principal de rendimiento debe ser:
- kg de limón fresco por árbol;
- toneladas de limón fresco por hectárea;
- kg totales de limón fresco si el usuario captura número de árboles.

La salida NO debe ser:
- número exacto de frutos;
- cajas, rejas, costales, bins o arpillas;
- precio o rentabilidad;
- Brix/acidez;
- porcentaje exacto de exportación;
- calibre exacto;
- jugo industrial;
- predicción comercial garantizada.

BIO-G puede mostrar porcentaje comercializable como contexto, pero no debe confundir kg biológicos con fruta vendible de primera.

0.4. Motor real de la librería
La `lib.zip` revisada muestra dos capas de rendimiento para árboles:

A) Capa mínima global:
`lib/core/yield/tree_yield_reference_catalog.dart`
- Usa `TreeYieldReference`.
- Estima kg totales = kg/arbol x número de árboles.
- Trabaja por `TreeProductiveTier`.
- Es conservadora y sirve como fallback/pantalla simple.

B) Capa completa por árbol:
`lib/core/crops/[tree]/[tree]_yield_reference.dart`
- Usa `YieldRange(low, expected, high)`.
- Usa `fullKgPerTree`.
- Convierte con `treesPerHaFromSpacing`, `tonHaFromKgTree`, `kgTreeFromTonHa`.
- Maneja `ProductionState`, `ManagementLevel`, `IrrigationLevel`, `StressMemory` y `DensitySystem`.
- Naranjo ya implementa `resolveOrangeTreeYield(...)` y es el patrón cítrico más cercano.

Corrección a la intuición del usuario:
Sí, vas bien: el motor completo se apoya mucho en árboles/ha, pero el eje más limpio es **kg/arbol fresco + árboles/ha = t/ha**. La pantalla simple puede calcular kg totales con número de árboles. La pantalla completa debe usar densidad o marco de plantación para evitar inflar t/ha.

0.5. Regla no negociable BIO-G
No usar `sowingDate` como eje de rendimiento del limón.

El eje correcto es:
estado perenne + etapa visible + perfil LM + densidad + manejo + riego + floración/cuajado + carga visible + memoria de estrés.

El limón puede tener flor, frutito, fruto en llenado y fruto listo para corte al mismo tiempo. La cosecha no cierra el cultivo.

0.6. Decisión de calibración v1
BIO-G v1 debe ser conservador:
- Si el usuario sólo dice “limón”, usar lm_skip conservador.
- Si no hay densidad o número de árboles, no prometer t/ha fino.
- Si no hay estado productivo ni carga visible, bajar confianza.
- Si hay HLB, raíz dañada, salinidad o floración golpeada, bajar rendimiento aunque NPK esté “bien”.
- Resultados >35-40 t/ha sólo deben aparecer con perfil específico, densidad real, manejo alto/fertirriego y baja memoria de estrés.
- Resultados >45-50 t/ha se deben etiquetar como potencial alto/tecnificado, no expectativa normal.

B) México / instituciones / extensión:
- SADER/SIAP, escenario mensual de limón 2024: referencia de rendimiento nacional agregado conservador.
- INIFAP, altas densidades en limón Persa: densidades 357, 666, 800 y 1000 árboles/ha; rendimientos convencionales y de alta densidad.
- INIFAP, manejo integral de limón mexicano con alta incidencia de HLB: rendimiento posible 15-25 t/ha con manejo, riego, nutrición y densidad, aunque con enfermedad.
- SENASICA / análisis de impacto económico de cancro: tabla de productividad por edad de limón persa usada en simulación oficial.
- Chapingo / DICEA: producción y agronomía de limón persa en Misantla, Veracruz.
- ASyD 2022: sustentabilidad de limón persa en Martínez de la Torre, Veracruz.

C) Universidades/extensión internacional:
- UF/IFAS, Tahiti/Persian lime: producción por árbol según edad; útil como límite biológico, NO como promedio mexicano de huerto.
- UF/IFAS, Key lime/Mexican lime: entrada a producción y producción por árbol; útil para comparar limón mexicano/Key lime, pero no para sustituir datos mexicanos de huerto.

D) Investigación aplicada:
- Trabajos sobre limón persa en Morelos: rendimiento por árbol, t/ha, programación de cosecha y efecto de nutrición/manejo.
- Trabajos sobre producción en época de oferta escasa: útiles para LM-05 desfase/inducido.

E) Foros y lenguaje de productor:
Se usaron sólo para UX y frases de campo, NO para umbrales duros.
Frases detectadas/útiles:
- “floreó mucho pero tiró el limoncito”
- “trae mucho limón pero no agarra tamaño”
- “sale seco / sin jugo”
- “está verde pero ya lo cortan”
- “se raja”
- “se amarillea por partes”
- “se quemó de la orilla”
- “tiene goma en el tronco”

Regla: los foros ayudan al copy farmer-friendly, no al cálculo.

2.2. Lectura crítica de los datos encontrados

Los datos de rendimiento de limón varían muchísimo. No existe un único número correcto.

Ejemplos que afectan la calibración:
- Datos oficiales agregados pueden verse bajos porque mezclan temporal, regiones, edades, condición sanitaria, superficie joven y variabilidad anual.
- En limón Persa convencional de Veracruz/zonas productoras, rangos de 18-25 t/ha son razonables con manejo.
- En alta densidad bien manejada de limón Persa, INIFAP reporta potenciales cercanos a 38-50 t/ha a siete años con 666-1000 árboles/ha.
- En limón mexicano con HLB, INIFAP reporta que un paquete de manejo puede sostener 15-25 t/ha dependiendo de densidad y manejo, pero eso no significa que HLB no reduzca potencial.
- En estudios de limón Persa, árboles de 7-11 años pueden reportar 80-140 kg/arbol o más, pero eso depende de portainjerto, temporada, edad y manejo.
- UF/IFAS reporta árboles Tahiti/Tahití grandes con kg/arbol muy altos; BIO-G debe tratarlos como límite biológico de árbol grande, no como default por hectárea.

Conclusión BIO-G:
El motor debe calcular por kg/arbol y árboles/ha, pero con caps por densidad. Un árbol aislado puede cargar mucho; una hectárea densa no puede asumir que cada árbol se comporta como árbol aislado.

- >30 t/ha: alto para muchos sistemas, pero posible en huertas buenas.
- >40 t/ha: potencial técnico/alta densidad; pedir confirmar densidad, árboles faltantes, riego, poda, sanidad y porcentaje comercializable.
- >50 t/ha: sólo con historial/datos; mostrar cautela fuerte.

4.1. Lectura por perfil

LM-SKIP
- Conservador.
- No asume Persa ni Mexicano.
- No asume densidad, riego, portainjerto ni manejo técnico.
- Útil para onboarding rápido.

LM-01 Persa/Tahití
- Perfil de mayor importancia exportadora.
- Fruto grande, verde comercial, generalmente sin semilla.
- Alto potencial con riego, poda, densidad y sanidad.
- Alta densidad puede subir t/ha, pero cada árbol carga menos; aplicar caps por densidad.

LM-02 Mexicano/Colima/Criollo
- Fruto chico, muy ácido, con semilla, cosecha frecuente.
- Puede ser muy productivo por hectárea si hay densidad y manejo.
- Más sensible a frío y con fuerte contexto HLB/psílido en México.
- No usar UF/IFAS Key lime como único dato porque huertas mexicanas intensivas pueden superar kg/arbol de paisajismo.

LM-03 Amarillo/Eureka/Lisbon
- True lemon/limón amarillo.
- Menos dominante en México; confianza menor.
- Puede tener buen potencial, pero BIO-G debe evitar asumir mercado amplio o manejo típico de Persa.

LM-04 Tropical/continuo
- No es necesariamente especie distinta; es comportamiento productivo en zonas cálidas con floraciones/cortes repetidos.
- Puede dar producción frecuente, pero también acumula estrés, plagas de brote, salinidad y agotamiento.

LM-05 Desfase/inducido
- Perfil de comportamiento/manejo, no especie botánica.
- No debe prometer más rendimiento anual: busca mover ventanas de cosecha.
- Estrés mal manejado puede bajar cuajado y rendimiento total.
- Idealmente futuro: modelar como modificador sobre LM-01 o LM-02. En v1 puede existir como perfil conservador.

6. ESTADOS PRODUCTIVOS PARA RENDIMIENTO
================================================================================

El estado productivo es local del motor de rendimiento. No inventar nuevos TreeStateIds globales.

[TABLA]
Estado rendimiento | Descripción BIO-G | Salida

6.1. Multiplicadores sugeridos

```dart
enum LemonProductionState {
  nonProductive,
  firstBearing,
  youngBearing,
  fullBearing,
  lowSetOrDropYear,
  offSeasonInduced,
  oldDeclining,
  unknown,
}

({double low, double expected, double high}) _productionStateFactors(
  LemonProductionState state,
) {
  return switch (state) {
    LemonProductionState.nonProductive => (low: 0, expected: 0, high: 0),
    LemonProductionState.firstBearing => (low: 0.08, expected: 0.25, high: 0.45),
    LemonProductionState.youngBearing => (low: 0.35, expected: 0.65, high: 0.90),
    LemonProductionState.fullBearing => (low: 0.75, expected: 1.00, high: 1.20),
    LemonProductionState.lowSetOrDropYear => (low: 0.15, expected: 0.45, high: 0.75),
    LemonProductionState.offSeasonInduced => (low: 0.20, expected: 0.55, high: 0.95),
    LemonProductionState.oldDeclining => (low: 0.30, expected: 0.60, high: 0.85),
    LemonProductionState.unknown => (low: 0.25, expected: 0.55, high: 0.85),
  };
}
```

6.2. Inferencia desde estado perenne

- newly_planted => nonProductive.
- juvenile_non_productive => nonProductive.
- established => unknown o firstBearing si el usuario reporta fruta.
- productive_season + fruit_fill/harvest_maturity/post_harvest => fullBearing por defecto conservador.
- productive_season + flowering/fruit_set => youngBearing o unknown si no hay carga confirmada.
- unknown => unknown.

6.3. Etapas que bloquean rendimiento

Si la etapa es:
- planting_transplant;
- root_establishment;
- juvenile_vegetative;

o si el estado es newly_planted / juvenile_non_productive, BIO-G proyecta 0 kg/arbol.

Mensaje:
“Todavía no proyectamos cosecha fuerte. En limonero joven primero importa raíz, copa, hoja sana y estructura antes que forzar producción.”

6.4. Edad orientativa

No usar edad como motor principal, pero puede orientar:
- 0-1 años: establecimiento, normalmente 0 comercial.
- 2-3 años: posible primera cosecha si injertado y bien manejado.
- 4-5 años: producción joven a plena según perfil, densidad y manejo.
- 6-8 años: plena producción en sistemas bien manejados.
- 9+ años: puede ser plena o declinar según poda, raíz, HLB, salinidad y copa.

7.1. Fórmulas

`arbolesPorHa = 10000 / (distanciaEntreHileras_m * distanciaEntreArboles_m)`

`tonHa = (kgPorArbol * arbolesPorHa) / 1000`

`kgPorArbol = (tonHa * 1000) / arbolesPorHa`

7.3. Caps por densidad

La densidad no sólo multiplica. A mayor densidad, cada árbol tiene menos espacio, luz y volumen de copa. El motor debe capear kg/arbol para no inflar t/ha.

```dart
class LemonDensitySystem {
  const LemonDensitySystem(this.id, this.kgPerTreeCap);

  final String id;
  final double kgPerTreeCap;

  static const extensive = LemonDensitySystem(
    'extensive_or_old_spacing_under_250_trees_ha',
    180,
  );
  static const traditional = LemonDensitySystem(
    'traditional_250_400_trees_ha',
    130,
  );
  static const commercialModerate = LemonDensitySystem(
    'commercial_400_650_trees_ha',
    95,
  );
  static const highDensityManaged = LemonDensitySystem(
    'high_density_650_900_trees_ha',
    55,
  );
  static const veryHighDensity = LemonDensitySystem(
    'very_high_density_over_900_trees_ha',
    50,
  );

  static LemonDensitySystem fromTreesPerHa(double treesPerHa) {
    if (treesPerHa < 250) return extensive;
    if (treesPerHa < 400) return traditional;
    if (treesPerHa < 650) return commercialModerate;
    if (treesPerHa < 900) return highDensityManaged;
    return veryHighDensity;
  }
}
```

7.4. Justificación de caps

Ejemplo sin cap:
- Persa alto: 115 kg/arbol x 1000 arboles/ha = 115 t/ha.
Eso no es una expectativa razonable de v1.

Con cap muy alta densidad:
- cap 50 kg/arbol x 1000 arboles/ha = 50 t/ha.
Ese resultado ya coincide mejor con rangos técnicos de alta densidad reportados para Persa, pero sigue siendo alto y debe pedir confirmación.

8. MODIFICADORES DE MANEJO
================================================================================

8.1. Manejo

```dart
enum LemonManagementLevel { low, medium, good, high, exceptional }

double _managementFactor(LemonManagementLevel? level) => switch (level) {
  null => 1.0,
  LemonManagementLevel.low => 0.55,
  LemonManagementLevel.medium => 0.85,
  LemonManagementLevel.good => 1.05,
  LemonManagementLevel.high => 1.18,
  LemonManagementLevel.exceptional => 1.28,
};
```

Lectura:
- low: manejo irregular, poca poda, riego malo, sanidad reactiva, baja nutrición.
- medium: manejo funcional promedio.
- good: riego, poda, nutrición y sanidad ordenadas.
- high: fertirriego/monitoreo/poda/sanidad/cortes ordenados.
- exceptional: sólo con datos confiables, no default.

8.2. Porcentaje de cuidado

100% cuidado = manejo correcto para el potencial base. No significa máximo teórico.

```dart
double _carePercentFactor(double? carePercent) {
  if (carePercent == null) return 1.0;
  final p = carePercent.clamp(0, 130).toDouble();
  if (p <= 30) return 0.40;
  if (p <= 50) return 0.60;
  if (p <= 70) return 0.78;
  if (p <= 90) return 0.90;
  if (p <= 105) return 1.00;
  if (p <= 115) return 1.12;
  if (p <= 125) return 1.20;
  return 1.25;
}
```

Si existen `managementLevel` y `carePercent`, no multiplicar ambos agresivamente. Usar `carePercent` como principal o tomar el menor.

8.3. Riego

```dart
enum LemonIrrigationLevel {
  rainfedHumid,
  rainfedDry,
  irregular,
  stable,
  fertigation,
}

double _irrigationFactor(LemonIrrigationLevel? level) => switch (level) {
  null => 1.0,
```

Regla limonero:
El agua pesa todo el año. En floración/cuajado tumba amarre; en llenado tumba calibre/jugo; en salinidad cambia absorción; en exceso da raíz/Phytophthora/gomosis.

13.1. Función esperada

```dart
LemonTreeYieldProjection resolveLemonTreeYield({
  required String? profileId,
  required String? perennialStateId,
  required String? phenologyStageId,
  double? treesPerHa,
  double? hectares,
  int? treeCount,
  LemonProductionState? productionState,
  LemonManagementLevel? managementLevel,
  double? carePercent,
  LemonIrrigationLevel? irrigationLevel,
  LemonBloomSetStatus? bloomSetStatus,
  LemonCropLoadStatus? cropLoadStatus,
  LemonCommercialQualityRisk? commercialQualityRisk,
  LemonTreeStressMemory? stressMemory,
})
```

13.2. Orden de cálculo

1. Normalizar stateId y stageId.
2. Resolver profileId; fallback a lm_skip.
3. Si estado/etapa bloquea rendimiento, devolver 0.
4. Inferir LemonProductionState.
5. Resolver densidad:
   - usar treesPerHa si existe;
   - si no, treeCount / hectares;
   - si no, dejar ton/ha como null o usar expectedTonPerHa sólo como orientación.
6. Aplicar factores:
   - estado productivo;
   - manejo/cuidado;
   - riego;
   - floración/cuajado;
   - carga visible;
   - memoria de estrés.
7. Calcular kg/arbol.
8. Aplicar cap por densidad.
9. Convertir a t/ha.
10. Calcular totalKg si hay treeCount.
11. Calcular commercialFruitPct como contexto.
12. Calcular confianza.
13. Agregar notas.

13.3. Cálculo base

```dart
final sf = _productionStateFactors(state);
final mgmt = _managementFactor(managementLevel);
final care = _carePercentFactor(carePercent);
final managementCombined = carePercent == null ? mgmt : care;
final irr = _irrigationFactor(irrigationLevel);
final set = _bloomSetFactor(bloomSetStatus);
final load = _cropLoadFactor(cropLoadStatus);
final stress = stressMemory?.yieldFactor01 ?? 1.0;
final commonFactor = managementCombined * irr * set * load * stress;

YieldRange kgTree = ref.fullKgPerTree
    .scaleEach(sf.low, sf.expected, sf.high)
    .scale(commonFactor);

if (density != null) {
  kgTree = kgTree.cappedAt(
    LemonDensitySystem.fromTreesPerHa(density).kgPerTreeCap,
  );
}
```

16. EJEMPLOS DE CÁLCULO
================================================================================

16.1. Persa convencional bien manejado

Entrada:
- profileId: lm_01_persa_tahiti
- producción plena
- 357 árboles/ha
- manejo good
- riego stable
- carga balanced

Base esperado: 70 kg/arbol.
Estado full expected: x1.00.
Manejo good: x1.05.
Riego stable: x1.02.
Carga balanced: x1.00.
Resultado esperado aprox: 70 x 1.05 x 1.02 = 75 kg/arbol.
Cap densidad 357 = 130 kg/arbol, no limita.
75 x 357 / 1000 = 26.8 t/ha.

Mensaje:
“Buen potencial para Persa. Confirma porcentaje comercializable, calibre, riego, salinidad y raíz.”

16.2. Persa alta densidad 800 árboles/ha

Base alto puede intentar 115 kg/arbol.
Sin cap: 115 x 800 / 1000 = 92 t/ha, inflado.
Cap 650-900 árboles/ha: 55 kg/arbol.
55 x 800 / 1000 = 44 t/ha.

Mensaje:
“Alta densidad detectada. Se limita kg/arbol para no tratar cada árbol como si estuviera en marco amplio.”

16.3. Mexicano/Colima con manejo funcional y 416 árboles/ha

Base esperado: 45 kg/arbol.
Manejo medium: x0.85.
Riego stable: x1.02.
Resultado: 39 kg/arbol.
39 x 416 / 1000 = 16.2 t/ha.

Mensaje:
“Rango funcional para limón mexicano. Si hay HLB, caída de frutito o salinidad, baja confianza y revisar sanidad/raíz.”

16.4. SKIP temporal seco con estrés de llenado

Base esperado: 35 kg/arbol.
Manejo low: x0.55.
RainfedDry: x0.45.
Estrés moderado: x0.65.
Resultado: 35 x 0.55 x 0.45 x 0.65 = 5.6 kg/arbol.
Con 300 árboles/ha = 1.7 t/ha.

Mensaje:
“Proyección baja. No se arregla sólo con fertilizante: revisar agua, salinidad, raíz, hoja y carga real.”

16.5. Desfase mal aplicado

Base esperado lm_05: 40 kg/arbol.
Estado offSeasonInduced expected: x0.55.
InducedBloomStressFailure: x0.50.
Riego irregular: x0.70.
Resultado: 40 x 0.55 x 0.50 x 0.70 = 7.7 kg/arbol.

Mensaje:
“El desfase no garantiza producción. Si el estrés se pasó, puede inducir flor pero perder cuajado.”

- No usar `sowingDate` como eje de rendimiento.
- No usar kg/arbol de naranjo para limón.

- No permitir >50 t/ha como default sin datos/historial.
